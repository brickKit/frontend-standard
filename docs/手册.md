# frontend-standard 手册

## 1. 项目结构

```
components/frontend/standard/
├── component.yaml / assembly.yaml   # brickKit 契约（configSchema、data_scopes 等）
├── Dockerfile / nginx.conf / docker-entrypoint.sh
├── pnpm-workspace.yaml
├── packages/
│   ├── design-tokens/    # 运行时可写 CSS 变量，零框架依赖，两端共享（决策 114）
│   ├── ui-kit-pc/        # AntDV v4 + vxe-table 的唯一落点：BeTable、四个页面模板、主题/渲染器接线
│   └── ui-kit-mobile/    # wot-design-uni 的主题桥接（组件走 easycom，见该包 README）
└── apps/
    ├── pc/    # 独立 Vite SPA，AWS Console 式骨架 + 本阶段业务页面
    └── mobile/ # Uni-app，H5 target，待办 + 通知两个页面组
```

`packages/design-tokens` 必须最先构建（`pnpm --filter @be/design-tokens build`），
`apps/pc`/`apps/mobile` 都直接引用它的编译产物（`dist/`），而不是引用 `ui-kit-pc`/
`ui-kit-mobile` 的编译产物——那两个包是"just-in-time"工作区包，直接引用 `src/`
（apps 用 Vite/uni-app 自己的 TS 编译，不需要一个额外的库打包步骤）。

## 2. 功能详解

### 2.1 登录与静默刷新（design.md §3.4）

```
① 未登录访问 → apps/pc 的 /login（apps/mobile 的 pages/login/index）
   → 整页跳转 Casdoor 的 /login/oauth/authorize（真实 PKCE：S256 code_challenge）
② Casdoor 回调带 code → 浏览器直接（不经我们后端）POST Casdoor 的
   /api/login/oauth/access_token 换 id_token
③ 用 id_token 调 infra-iam-casdoor 的 POST /api/iam/token → 拿应用 token + refresh token
④ access token 只放内存（Pinia/reactive 单例），refresh token 放 localStorage
⑤ 401 且 WWW-Authenticate 带 error="token_stale" → 静默刷新 → 重试原请求恰好一次
```

真机联调过完整链路（阶段三 Task 12）：真实 Casdoor 登录页、真实 token 交换、真实
`/api/tenant/features`/`/api/me/permissions` 调用。②③两步的端点路径/参数在最初实现时
是"文档摘要，未逐字核对"，已用 Playwright 真机浏览器测试核对过是真实生效的。

### 2.2 动态路由/菜单（design.md §3.3）

`apps/pc/src/router/menuRegistry.ts` 是一份手工维护的登记表——真实的最终形态是
`be-ops` 生成期聚合 62 份 `assembly.yaml` 的 `menus` 段产出，但那个生成器本身不在
`frontend-standard` 的改动范围内（是 `be-ops` 自己的工具链任务），手工登记表在功能上
等价，登记的 `componentId`/`permission` 逐条核对自各组件真实的 `assembly.yaml`（不是
`registry/permissions.tsv`——那份表在实现时发现滞后于阶段三新组件，已用
`be-ops permissions` 重新生成过，见根 `docs/dev/实测踩坑记录.md` 相关记录）。

可见路由 = `access.visibleMenu`（`features.has(componentId) && permissions.has(permission)`
的交集），登录后一次性拉取两份数据、注册一次 `vue-router` 动态路由（`registerBusinessRoutes`）。

### 2.3 PC 骨架（design.md §3.5，§12.6.7）

`AppLayout.vue`：顶部服务选择器（按 `menuRegistry` 的 `group` 分组，Dropdown 悬停展开）+
组织/法人切换器（⚠️ 目前只是 UI 状态，未接入任何真实的法人维度请求参数——见
`stores/orgContext.ts` 的注释，erp-finance 的真实契约里没有暴露对应的覆盖参数）+ ⌘K
全局搜索（`Ctrl/Cmd+K` 打开一个跨全部可见菜单项的模糊搜索弹层）+ 应用内标签页
（`stores/tabs.ts`，决策 113 第二处必改）+ 服务内扁平菜单（左侧 Sider，同一 `group`
下的条目平铺，不做多级树，决策 113）。

### 2.4 移动端（design.md §1.1）

Uni-app H5 target，`unh.config.js` 锁死 `platform.default: "h5"`。`pages.json` 的
`easycom.custom` 正则把 `wd-*` 标签映射到 `wot-design-uni/components/wd-$1/wd-$1.vue`，
业务代码里不需要任何 `import`。底部 `tabBar` 两个入口（待办/通知），登录/回调两个页面
用 `navigationStyle: custom` 隐藏原生导航栏。

## 3. 完整契约清单

**本组件不发布任何契约**（design.md §3："我是纯静态资源，不提供任何接口"）。以下是
**消费**的真实端点，逐条对应各组件已发布的契约文件：

| 端点 | 来源组件 | 用途 |
|---|---|---|
| `GET /login/oauth/authorize`、`POST /api/login/oauth/access_token` | Casdoor（浏览器直连，不经网关） | OIDC 授权码 + PKCE |
| `POST /api/iam/token` / `POST /api/iam/token/refresh` / `POST /api/iam/logout` | `infra-iam-casdoor` | 换应用 token / 刷新 / 登出 |
| `GET /api/tenant/features` | `infra-iam-casdoor` | 装配级特性开关，`besdk.Public` |
| `GET /api/me/permissions` | `infra-authz` | 用户级权限键集合 |
| `GET/POST /api/admin/roles/**`、`GET/POST/DELETE /api/admin/users/{sub}/**` | `infra-authz` | 角色管理页 |
| `GET/POST /erp/sales/orders/**`、`POST .../confirm`、`POST .../ship`、`POST .../cancel` | `erp-sales` | 销售订单列表/详情/操作 |
| `POST /infra/print/render` | `infra-print` | 打印送货单（需要一份真实上传过的 `sales.delivery_note` 模板，本阶段未播种） |
| `GET /infra/workflow/tasks/**`、`POST .../approve`、`POST .../reject` | `infra-workflow` | 待办列表/详情/操作 |
| `GET/PUT /infra/notification/notifications`、`GET/PUT /infra/notification/preferences` | `infra-notification` | 通知历史/偏好 |
| `GET /mdm/customer/customers/**` | `mdm-customer` | 客户只读查询 |
| `GET /mdm/product/products` | `mdm-product` | 产品只读查询 |
| `GET /erp/inventory/balances`、`GET /erp/inventory/movements` | `erp-inventory` | 库存查询 |
| `GET /erp/finance/ar-ledger` | `erp-finance` | 应收查询 |

字段/参数命名逐字对照各组件 `contracts/*.openapi.yaml`，改动这些端点前先去看对应组件
的真实契约文件，不要凭记忆改。

## 4. 数据模型

**无数据库**（design.md §2）。客户端状态分三层：

| 层 | 存哪 | 实现 |
|---|---|---|
| 装配期配置 | 构建产物 + 容器启动时注入 | `window.__BE_CONFIG__`（`src/config.ts`） |
| 登录态 | 内存（access token）+ `localStorage`（refresh token） | `apps/pc/src/stores/auth.ts`（Pinia）/ `apps/mobile/src/auth/state.ts`（reactive 单例） |
| 纯本地 | `localStorage` | 目前只有 refresh token；未来的表格列宽/草稿也走这里，不放业务数据当缓存 |

`access ∩ features` 的两份原始数据（`Set<string>`）存在 `stores/access.ts`，不落任何
持久化层——每次登录/刷新页面都重新拉取，不担心"缓存过期"这类问题，因为压根没有缓存。

## 5. 开发

```bash
pnpm install
pnpm --filter @be/design-tokens build
pnpm -r --if-present run typecheck   # 3 个有 tsconfig 的包/应用
pnpm -r --if-present run test        # design-tokens / ui-kit-pc / apps/pc 三处真测试
```

新增一个 PC 页面：① 在对应组件的真实 `contracts/*.openapi.yaml` 找端点 → ②
`apps/pc/src/api/<domain>.ts` 写类型 + 请求函数（照抄现有文件的模式：金额/数量一律
`string`）→ ③ 页面用 `BeListPage`/`BeDetailPage` + `BeTable` 起手 → ④
`menuRegistry.ts` 登记菜单项 → ⑤ `router/index.ts` 的 `PAGE_COMPONENTS` 登记懒加载
组件 → ⑥ 所有 `load()`/`reload()` 函数必须有 `catch`（真机测试踩过的坑，见根
`docs/dev/实测踩坑记录.md` A14：后端拒绝是正常路径，不是异常路径）。

## 6. 排障

| 症状 | 原因 | 怎么查 |
|---|---|---|
| 登录跳转到 Casdoor 后报 "Failed to sign in" | `casdoorClientId` 没配 或 `redirect_uri` 没在 Casdoor 那边登记 | `curl` Casdoor 管理 API 的 `get-application` 核对 `clientId`/`redirectUris` |
| 菜单看得见、点进去 403 | 后端真实拒绝（正常——前端判定不是安全边界） | 看 `/api/me/permissions` 返回的 `keys` 是不是真的包含这个页面要求的权限键；再看后端组件自己的 `assembly.yaml` 权限键是不是写对了 |
| `pnpm dev` 时移动端 `window.__BE_CONFIG__` 读不到，控制台一堆 500 | uni-app 的 Vite 插件把 `<script src>` 都当模块请求预处理，跟 Vite 的 public 文件规则冲突 | 已知坑（根 `docs/dev/实测踩坑记录.md` A15），已经改成内联配置，若又倒退回 `<script src>` 写法会复现 |
| 加了 `apps/mobile` 之后 `apps/pc` 的 `vue-tsc` 突然报 `App<any>` 不兼容 | 同一个 pnpm workspace 里两个应用锁了不同的 `vue` 精确版本，类型检查阶段互相污染 | 已知坑（A16），两边的 `vue` 版本必须保持一致 |
| `make image` 建出来的容器 `/healthz` 502 | Nginx 配置或 entrypoint 脚本有语法错误，容器没真正起来 | `docker logs` 看 nginx 是否成功启动；`docker exec` 进容器手动跑一遍 `docker-entrypoint.sh` 看报错 |
